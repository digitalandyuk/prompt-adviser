# Independent forward-test report: 0.7.0 candidate

## Method and limits

An independent Codex-hosted evaluator read the generated Codex skill, shared prompt/tool/source/Jev references and the Claude/Antigravity routing appendices. It generated six fictional multi-turn review conversations, two per edition, with a questioning response, fictional user answers and explicit finalisation. Traces are recorded in files 01–06, with targeted corrections in 07–08.

These are text simulations generated by the evaluating agent, not separate native Claude/Antigravity sessions or a controlled before/after task-quality benchmark. No reviewed workflow, browser/CMS action, connector call, repository edit, image generation, installer, external publication or paid Jev call was executed. No public source lookup or model metadata verification was available in the fictional target environments. The simulations therefore exercise the honest offline checkpoint, not fresh live lookup/licence behaviour.

## Candid adherence issues

1. **Case 03 completeness overstatement.** The user supplied the XLSX format and fallback but omitted the save destination. The finished prompt correctly defers writing until an agreed location exists, yet finalisation said 100%. File 07 corrects that to 95% and exposes the gap. The original is retained. The candidate already requires the actual destination, so this is an adherence slip rather than grounds for another universal rule.
2. **Case 05 irrelevant alternative role.** The checkpoint offered an otherwise suitable community-brand designer plus an irrelevant developer-tools product designer. The user selected the suitable role, so the final prompt has no downstream defect. File 08 retests the checkpoint using one suitable role plus No role. Existing instructions permit one role and require relevance; no new rule is proposed.
3. **Case 01 diagnostic caution.** The initial 1/2 consistency judgment is debatable: “return only the note” and invisible repeated checks can technically coexist. Redundant process is clearly excess context, but it is not a hard logical contradiction. Treat this as diagnostic calibration needing further observation, not evidence that every procedural inefficiency is an instruction clash. The final prompt appropriately removes the unnecessary process while retaining the output requirements.
4. **Offline model limitation.** Every trace retains the selected host model and explicitly marks exact version/controls unverified. It cannot literally provide a verified-current alternative without metadata or browsing. This inherited requirement is not demonstrated by these fixtures.

## Interpretation

The traces demonstrate the intended review behaviours being expressed by a Codex-hosted evaluator and expose a few ordinary adherence/calibration slips. They do not prove user outcome gains, calibrated completeness, native discovery or runtime capability. Further repeatable evaluations should score actual task results on fixed inputs and retain per-case failures, instead of treating this small pass or package checks as a performance guarantee. The demonstrated slips are already covered by existing instructions; adding blanket rules would bloat the skill without a proven general benefit.
